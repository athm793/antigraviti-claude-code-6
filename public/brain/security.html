Security

Ownership (the structural control)

  • Every provider and endpoint has an owner_user_id. Admins see all; everyone else sees their own. Ownerless rows are admin-only, never open.
  • authorizeConfig / authorizeEndpoint run first in every dashboard route. A row you can't access returns 404, not 403, so ids can't be probed.
  • checkStepProviders guards the seam JSONB leaves open: a definition names providers by id with no FK, so both the save route and the test route verify every config_id belongs to the caller. Without it, anyone could write a step carrying someone else's provider id and spend their keys. The refusal says "isn't available", the same wording for deleted and never-yours, so it can't be used to test id existence.

Two fixed pre-existing criticals (2026-07-25)

  • GET /api/configs/[id]/keys returned every upstream key in plaintext to any logged-in user → key previews (••••1234) only; raw values are server-side only.
  • Any user could repoint any config's target_base_url and harvest its keys → ownership on every route + egress checks + a distinct target_host_changed audit event.

Egress (SSRF)

  • checkPublicHttpTarget on save: rejects loopback, link-local (incl. 169.254.169.254), RFC1918, CGNAT, .internal, credentials-in-URL, own host.
  • assertResolvesPublic re-resolves DNS at request time for waterfall steps — the save-time check alone loses to DNS rebinding.
  • isWithinBase containment: a resolved path can never restructure the URL off the provider's origin/base path. Redirects are refused, not followed.

Keys

Endpoint keyskp_ep_<hex keyId>_<32B base64url> — public id + SHA-256 hash, shown once, constant-time verify, revocable. SHA-256 not scrypt on purpose: 256 bits of entropy, hot path. keyId is hex because base64url contains _, the field separator.
Key scopingA key identifies its endpoint; the URL segment must agree (slug or id) — a key for endpoint A can't run endpoint B.
Master keysLegacy plaintext pattern on providers, kept for proxy compatibility; masked in UI.

Injection defences (all tested)

  • JSON bodies object-walked, never string-spliced — a test feeds a value crafted to add an isAdmin key and asserts it can't.
  • Path traversal: segments encoded individually, .. rejected; query via URLSearchParams; CR/LF in header values rejected.
  • Prototype pollution: __proto__/constructor/prototype blocked read+write, null-prototype contexts, scrubber rebuilds objects null-prototyped.
  • Template roots closed — no env, no process.

Fail-closed gates

  • /api/cron/prune: no CRON_SECRET → 404 for everyone.
  • /api/debug: off unless ENABLE_DEBUG_ROUTE=true.
  • Middleware public prefixes keep their trailing slash — matching is startsWith, so /api/run without one would also expose /api/runners.

Data-handling stances

  • Run logs by allowlist; results stored only on opt-in; retention default 30 days, enforced nightly.
  • Secret scrubbing on everything leaving the process (redact.ts) — a net for accidents (echoed headers, keys in error messages), not a guarantee against a hostile upstream that base64s a key. Ownership is the real control.
  • Rate limiting for spend is DB-backed per key; the in-memory IP limiter is only used for session-authenticated dashboard buttons.
