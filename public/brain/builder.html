Builder UI

src/components/builder/ — the Build tab of an endpoint. All editing is local state; only Save touches the wire.

Shape

  • EndpointBuilder owns the draft and never re-seeds from props after mount (a router.refresh() re-renders the server shell around the island).
  • Steps render grouped into stages, mirroring the engine: sequence steps get stage numbers, parallel-group members get letters (a numbered list would claim an order that doesn't exist).
  • Collapsed step rows read as prose: "Runs if step 1 didn't answer", "Runs with the steps beside it".
  • Live validation via the shared validator; Save disabled with a reason while errors exist; per-step issues render on their card.
  • Renaming a step's reference key rewrites every template that points at it (renameStepKey).
  • {{-autocomplete (TokenInput) scoped to what's actually available at that step's position — inputs, prior non-sibling steps, response.*.
  • All popovers portal through components/ui/Popover.tsx (fixed, rect-positioned, flips near edges) — tables clip absolute-positioned dropdowns.

Visual | JSON toggle

  • Visual → JSON is live; JSON → visual needs an explicit Apply (a half-typed brace must not wipe the visual state).
  • Both views stay mounted with one hidden — unmounting would collapse expanded steps, drop the last test result, and silently discard unapplied JSON text.
  • If the builder changes under unapplied text, the text is left alone and a staleness callout appears; Apply of stale text is the second-worst outcome after overwriting typed text.
  • Import loads a file into the editor, not into the builder. Foreign config_ids are called out up front with the step names — provider ids don't travel between accounts.

Parallel groups (ParallelGroup.tsx)

A group is a container, not a per-step flag. Header: member count, the Take: merge-mode select, and the cost warning ("About $0.17 per run — every one of them is called") because "parallel = you pay everyone, every time" is the expensive misunderstanding. Joining/splitting is a toggle on each non-first step; a group left with one member is dissolved.

Test runs (TestRunPanel.tsx)

  • Tests the unsaved draft via POST /api/endpoints/[id]/test — nothing persisted, so experiments can't pollute hit rates, and you don't have to publish to find out if it works.
  • Live calls, real credits — the panel says so.
  • Per-step rows open to the condition traces ("Should it run?" / "Did it answer?"), unresolved placeholders, the actual URL, and the response preview (test runs always include bodies — it's the author debugging their own providers).
  • Step cards show the last test outcome in a reserved fixed-width slot; any edit clears it — a stale badge reads as "this still works".

Known UI rules honoured here

  • 44px min targets everywhere; inline SVG icons only; no native selects; portal popovers; reserved slots so results/statuses appearing never shift controls; tabular numerals on all counts.
